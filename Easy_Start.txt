==================================================
2) Physical VO - Controlled Manual Test (recommended first)
==================================================
When to use:
- First validation after boot.
- Slow and controlled movement checks.

Important launch fact:
- qcar2_manual_cartographer_launch.py includes qcar2_manual_drive_launch.py.
- That means it launches manual drive stack + cartographer together.

A) Terminal 1 - base + cartographer (includes rgbd)
source /opt/ros/humble/setup.bash
export PYTHONPATH=$PYTHONPATH:/usr/local/lib/python3.8/dist-packages
export ROS_DOMAIN_ID=67
cd ~/ros2
source install/setup.bash
ros2 launch qcar2_nodes qcar2_manual_cartographer_launch.py

B) Terminal 2 - VO node in physical mode
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=67
cd ~/ros2
source install/setup.bash
ros2 run qcar2_autonomy vo_node --ros-args -p camera_mode:=physical -p alignment_mode:=auto -p depth_scale:=0.0

C) Terminal 3 - VO diagnostics
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=67
cd ~/ros2
source install/setup.bash
ros2 topic echo /vo/fault_status

D) Optional health checks
ros2 topic hz /camera/color_image
ros2 topic hz /camera/depth_image
ros2 node list

Movement sequence (controlled):
1. Static hold 30-60 s
2. Slow straight
3. Gentle turns
4. Moderate speed only if diagnostics look stable

Manual control note (important):
- In this launch path, "manual drive" is the joystick command node, not WASD keyboard teleop.
- Source behavior from `qcar2_nodes/src/command.cpp`:
  - Hold `LB` to arm motion.
  - Use `RT` for throttle (press gently for slow speed).
  - Use left stick X (LLA) for steering.
  - Press `A` to reverse direction.

2.1) Physical VO - Keyboard Manual Drive (WASD, no controller)
==================================================
When to use:
- You do not want to use the game controller.
- You want terminal keyboard control (`w a s d`) at low speed.

Launch path note:
- Use keyboard-specific bringup so joystick command node is not active.
- This path includes `nav2_qcar2_converter` for `/cmd_vel_nav` to motor command conversion.

A) Terminal 1 - base + cartographer (keyboard path)

export ROS_DOMAIN_ID=67
cd ~/ros2
source install/setup.bash
ros2 launch qcar2_nodes qcar2_keyboard_cartographer_launch.py

B) Terminal 2 - VO node in physical mode
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=67
cd ~/ros2
source install/setup.bash
ros2 run qcar2_autonomy vo_node --ros-args -p camera_mode:=physical -p alignment_mode:=auto -p depth_scale:=0.0

C) Terminal 3 - VO diagnostics
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=67
cd ~/ros2
source install/setup.bash
ros2 topic echo /vo/fault_status

D) Terminal 4 - keyboard driver (slow defaults)
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=67
cd ~/ros2
source install/setup.bash
ros2 run qcar2_autonomy manual_drive

Keyboard controls:
- `w`: forward
- `s`: reverse
- `a`: turn left in place
- `d`: turn right in place
- `space` or `x`: stop
- `q`: stop and quit

Optional slower/faster tuning (Terminal 4):
ros2 run qcar2_autonomy manual_drive --ros-args -p forward_speed:=0.08 -p reverse_speed:=0.06 -p turn_rate:=0.20

Does car need to be on mat center for this section?
- Prefer yes for repeatability, but not mandatory for node startup.

==================================================
4) Physical Depth Probe (optional, isolated)
==================================================
Purpose:
- Validate depth conversion path (raw vs meters) separately.

Strict isolation rule:
- Run probe alone for camera stream ownership.
- Stop cartographer/manual launch and normal rgbd first.

If you want probe-only validation, run only these after sourcing:
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=67
cd ~/ros2
source install/setup.bash
ros2 run qcar2_nodes rgbd_get_meters_probe --ros-args -p device_type:=physical -p frame_width_depth:=640 -p frame_height_depth:=480 -p frame_rate:=30.0

Optional monitor terminal:
ros2 topic echo /camera/depth_probe_status

Does car need to be on mat?
- Not required. Car should be stationary and safe.

If rgbd_get_meters_probe fails:
1. Check stream conflict (another node still owning camera).
2. Use rs-enumerate-devices logs as calibration source of truth.
3. Continue physical VO with:
   - camera_mode:=physical
   - depth_scale:=0.0 (use mode default)
4. Re-run controlled sequence in Section 2 and evaluate /vo/fault_status.


==================================================
5) Safe Shutdown Before Closing Remote Desktop
==================================================
In each terminal, press Ctrl+C and wait for prompt return.

Recommended stop order:
1. /vo/fault_status echo
2. vo_node
3. planner/autonomy (if running)
4. cartographer/base bringup

Optional final check:
ros2 node list

If something is stuck, graceful cleanup command:
pkill -f 'vo_redundancy_monitor_depth|rgbd_get_meters_probe|cartographer_node|qcar2_hardware|rgbd|lidar|csi|joystick_command'

After processes stop, it is safe to disconnect remote desktop.
